# Ember 0.2.7 handover

v0.2.7 adds account sync to the v0.2.6 player/catalog build. See SUPABASE-SETUP.md and supabase/ember-supabase-setup.sql. Apply SQL manually in the intended Supabase project; public keys cannot perform database administration. Email delivery and OTP templates require dashboard configuration. The installer contains only the supplied public project URL/key.

src/sync-core.mjs projects per-setting/addon/library/progress/profile records, persists a pending queue in state._sync, uses stable JSON equality, and protects edits made while an upload is in flight. src/CloudAccount.tsx handles authentication, first-login download/initial seed, account-specific local archives, automatic mutation upload, daily/weekly/manual reconciliation, network backoff, conflict review and email/recovery code entry. Auth sessions use the Supabase client's device-local persistent storage; never embed administrator keys. Sign out retains local profile data. Project admins can read addon secrets; no end-to-end encryption is claimed.

SQL has a per-user revision head locked transactionally to prevent cursor/commit ordering gaps, idempotent mutation IDs, compare-and-swap revisions, persistent tombstones, 500-record pagination and ownership-checked authenticated-only RPC access. Direct anonymous/authenticated table writes are revoked; row-level security remains enabled. A conflict retains the local version until the user explicitly selects cloud/local. Cloud progress revisions and account changes take precedence over stale SQLite timestamps; normal newer checkpoint protection remains otherwise.

The SQL is rerunnable. It does not drop or migrate any legacy watch_progress data; existing local profiles seed new accounts. Old optional progress-only client upload code is removed. Device-only native-player preference and Trakt tokens/client ID are excluded from synchronization. Progress omits duplicated episode lists; opening remote continue-watching fetches metadata to restore episode navigation.

32 unit/integration tests include a local PostgreSQL-compatible PGlite database: SQL applies twice, separate accounts cannot cross-read via RPC, guests/direct writes are denied, retries do not duplicate revisions, stale writes conflict, pagination crosses 500 rows, and deletions persist. Five Electron account scenarios verify sign-in/first upload, per-record changes, durable offline queue/restart, conflict resolution and sign-out retaining local data. Existing player regression suite remains required after packaging. Native Windows and real SMTP/live project validation remain unverified until user setup.

Build: npm ci; npm test; npm run build; npx electron-builder --win dir --x64; node scripts/brand-windows.mjs; node tests/validate-package.mjs; node tests/packaged-runtime.mjs; python3 scripts/make-installer.py; python3 scripts/verify-installer.py; python3 scripts/package-source.py. NSISDIR/EMBER_MAKENSIS/EMBER_7Z may need local paths. No production dependency was added. PGlite is dev/test-only. Prior handovers cover native player, artwork, all-catalog discovery, removed subtitle-sync/hover-preview workers and portability. Those retired features remain absent. Linux/Android native adapters are not delivered by this Windows build.
